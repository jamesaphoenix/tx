## Purpose

An invariant states what must remain true, who enforces it and how to verify it.
Keep invariants in the design specification; map them beside the code and tests.

## Commands

```bash
tx spec invariant list
tx spec discover --doc checkout-design
tx spec gaps --doc checkout-design
tx spec matrix --doc checkout-design
```

## Workflow

Add an embedded YAML block to the generated design document:

```yaml
invariants:
  - id: INV-CHECKOUT-001
    statement: payment retries preserve exactly one order
    severity: high
    verified_by:
      - test/checkout.test.ts
```

Put `// @spec INV-CHECKOUT-001` beside the implementation that enforces the rule.
Put `[INV-CHECKOUT-001]` in a test title with assertions that would fail if the rule
were broken. Run discovery, inspect the matrix and fill meaningful gaps.

A mapping identifies coverage; it does not prove a passing result. Execute the
mapped tests and record their results through [tx spec](./spec-trace). The
`verify-invariants` skill covers both code mapping and verification.
