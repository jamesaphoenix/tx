## Purpose

Invariants are rules extracted from structured documentation (PRDs and design docs). Each invariant has an enforcement level and optional subsystem ownership. Invariants are managed through [`tx spec`](/docs/primitives/spec-trace).

Invariants enable:

- **Doc-to-test traceability** — each invariant maps to a testable assertion
- **Enforcement levels** — audit, warn, error, or block
- **Check recording** — track pass/fail results over time
- **Subsystem scoping** — filter invariants by owning subsystem

## Usage

<Tabs groupId="interface" persist items={["CLI", "TypeScript SDK", "MCP", "REST API"]}>

<Tab value="CLI">

```bash
# Discover invariants from docs and link to tests
tx spec discover

# Run all checks (drift, EARS, coverage, spec-test status)
tx spec lint

# List uncovered invariants
tx spec gaps

# Show full traceability matrix
tx spec matrix

# Record a test run result
tx spec run test/auth.test.ts::"login works" --passed

# Batch import test results
vitest run --reporter=json | tx spec batch --from vitest

# Check coverage and phase status
tx spec fci
tx spec status
```

</Tab>

<Tab value="TypeScript SDK">

```typescript
import { TxClient } from '@jamesaphoenix/tx-agent-sdk'

const tx = new TxClient({ dbPath: '.tx/tasks.db' })

// List all invariants
const all = await tx.invariants.list()

// Filter by subsystem or enforcement
const authInvariants = await tx.invariants.list({
  subsystem: 'auth',
  enforcement: 'error',
})

// Get a specific invariant
const inv = await tx.invariants.get('INV-AUTH-001')

// Record a check result
const check = await tx.invariants.record(
  'INV-AUTH-001',
  true,           // passed
  'All tokens validated',  // details (optional)
  1200,           // durationMs (optional)
)
```

</Tab>

```json
{
  "name": "tx_invariant_list",
  "arguments": {
    "subsystem": "auth",
    "enforcement": "error"
```

| Arg | Type | Required | Description |
|-----|------|----------|-------------|
| `subsystem` | `string` | No | Filter by subsystem |
| `enforcement` | `string` | No | Filter by enforcement level |

**Tool name:** `tx_invariant_get`

```json
{
  "name": "tx_invariant_get",
  "arguments": {
    "id": "INV-AUTH-001"
  }
}
```

**Tool name:** `tx_invariant_record`

```json
{
  "name": "tx_invariant_record",
  "arguments": {
    "invariantId": "INV-AUTH-001",
    "passed": true,
    "details": "All tokens validated",
    "durationMs": 1200
  }
}
```

| Arg | Type | Required | Description |
|-----|------|----------|-------------|
| `invariantId` | `string` | Yes | Invariant ID to record against |
| `passed` | `boolean` | Yes | Whether the check passed |
| `details` | `string` | No | Descriptive text (max 10000 chars) |
| `durationMs` | `number` | No | Check duration in milliseconds |

## Enforcement Levels

| Level | Behavior |
|-------|----------|
| `audit` | Recorded but no action taken |
| `warn` | Warning emitted on failure |
| `error` | Error reported on failure |
| `block` | Blocks downstream operations on failure |

## Invariant Lifecycle

Invariants are derived from doc YAML, not created manually:

1. Define invariants in a PRD or design doc markdown file
2. Run `tx spec discover` to extract them into the database and link to tests
3. Run `tx spec run` or `tx spec batch` to record pass/fail results
4. Run `tx spec lint` to check overall health
5. Run `tx spec complete` to sign off when coverage is full

## Related Commands

- [`tx doc`](/docs/primitives/docs): Manage the structured docs that invariants are derived from
- [`tx spec`](/docs/primitives/spec-trace): Spec-to-test traceability built on top of invariants
