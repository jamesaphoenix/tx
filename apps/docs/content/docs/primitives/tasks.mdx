## Purpose

Turn a saved implementation plan into small tasks with observable acceptance criteria.

## Commands

```bash
tx task add "Implement checkout" --description "Acceptance: a customer can pay."
tx task list
tx task ready
tx task show <task-id>
tx task update <task-id> --status active
tx task dep block <dependent-id> <blocker-id>
tx task dep tree <task-id>
tx task done <task-id>
```

Use `tx task --help` for reset, delete, bulk, parent and label operations.

## Workflow

Attach each task to its [plan](./plans) with `tx doc attach <task-id> <plan-ref>`.
Parent tasks express hierarchy; dependencies express blockers. Every task response
includes blockers, blocked tasks, children and linked docs. Dashboard cycles group
work into planning periods. Click the title in task details to rename it.

New tasks start in `backlog` with score `0`. Higher integer scores appear first.
Use `tx task update <task-id> --description=""` to clear a description.
For a title beginning with a dash, use `tx task add -- "--A task title"`.

Bulk operations validate every task ID before changing tasks. Bulk scores must be
safe integers; decimals and trailing text are rejected. Once inputs validate,
individual task failures are reported alongside successful changes in the
`succeeded` and `failed` JSON lists. Inspect both lists before retrying.

Weekly cycles are optional. Reading tasks or cycles does not create a planning
period. Create a cycle explicitly; its auto-add selection includes every matching
task. An empty auto-add selection disables automatic membership.
