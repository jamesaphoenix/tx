---
title: tx skills
description: Install three small guides for creating tasks, creating docs and verifying invariants
---

`tx init --claude` and `tx init --codex` install exactly three skills:

| Skill | Purpose |
| --- | --- |
| `tx-tasks` | Create tasks with acceptance criteria, document links and optional dependencies. |
| `tx-docs` | Create configured documents, including paired PRD and design documents for feature work. |
| `verify-invariants` | Map invariants to enforcement code and meaningful tests, then record verification evidence. |

The content is identical for both hosts. Default onboarding installs only skills
and a manifest. It does not install agents, rules, hooks, Ralph or a harness.
Existing repository runners and explicit watchdog integrations are separate from
this bundle. Legacy top-level context files remain optional compatibility inputs.

## Generate or refresh

```bash
tx skills generate --output-dir .tx/generated-skills --clean
tx skills generate --target codex --json
tx skills sync --project-dir /absolute/path/to/project
tx skills sync --target claude
```

Generation writes `<output-dir>/claude/.claude/skills/` and
`<output-dir>/codex/.codex/skills/`, each with three `SKILL.md` files and a manifest.
Skills are a CLI-only surface; use CLI help for the full primitive catalogue.

Sync adds missing files, updates changed files and preserves unrelated custom
skills. It removes known retired skill directories only when a valid previous
tx manifest lists their exact installation path. Malformed manifests and symbolic
links are rejected before changes. Older manually installed guides need an
explicit, repository-scoped cleanup; sync does not guess their ownership.

## Live document configuration and verification

`tx-docs` consults `tx spec types --json` and `tx doc template <type>`. It does
not embed a second copy of project templates. Use unique document references,
link paired documents and run `tx doc sync` and `tx spec lint` after editing.

`verify-invariants` maps each declared invariant to the actual enforcement site
with an `@spec` comment and to assertions in executable tests. Multiple code and
test mappings are supported. Tags establish traceability; passing checks or
explicitly labelled structural review establish verification evidence.

With worktrees, keep task state in the main repository and select the content
checkout with `--state-root` and `--content-root`. See [tx doc](/docs/primitives/docs)
and [tx spec](/docs/primitives/spec-trace) for the underlying commands.
