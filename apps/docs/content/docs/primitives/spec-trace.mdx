## Purpose

Connect specifications to the code and tests that implement them, then track
executed evidence separately from human approval.

## Commands

```bash
tx spec lint
tx spec discover --doc checkout-design
tx spec gaps --doc checkout-design
tx spec matrix --doc checkout-design
tx spec tests INV-CHECKOUT-001
tx spec status --doc checkout-design
```

Import an actual test report through standard input:

```bash
vitest run --reporter=json --outputFile=.tx/spec-results.json
tx spec batch --from vitest < .tx/spec-results.json
```

Vitest 5 writes JSON to a file. Import failed runs as well as passing ones; in an
automated check, preserve the test runner's exit code. Results must match the
mapped file and assertion. A matching title in another file is not evidence.

Use `tx spec --help` for explicit links, scoped results and supported report formats.

## Workflow

Map invariant IDs to enforcement sites and assertions using [invariants](./invariants).
Run the real tests and import their results; never mark a mapping as passing just
because its tag exists. Failed or missing results keep the specification in BUILD.

Passing evidence moves it to HARDEN. Once the work has been reviewed, record human
sign-off with `tx spec complete --doc checkout-design --by <reviewer>`. Sign-off is
separate from test execution. [tx spec health](./spec-health) summarises the state.

The matrix keeps production `@spec` comments under `sourceRefs`, separate from
executable tests. Source references cannot be imported as passing tests. An
invariant with only an enforcement annotation remains an uncovered testing gap.
